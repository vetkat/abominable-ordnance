# Graphics for design version 1: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wire the v1 art on `art/v1-graphics` into the prototypes, and ship
it with its credits.

**Architecture:** A new pure module, `core/prototypes/graphics.lua`, holds the
sheet values and builds every look, sound table, corpse and icon path. The
builders in `core/prototypes/` use those looks and stop tinting them.
`data.lua` passes only the vanilla sounds and the remnants name.
`tools/package.py` ships the licence files and `sound/`.

**Tech Stack:** Lua 5.2 with busted (`spec/`), the Factorio 2.1 data stage,
Python with pytest (`tools/tests/`).

**Spec:** `docs/superpowers/specs/2026-11-26-v1-graphics-design.md`. Read
it first. It has every sheet value, scale and shift, and the decisions.

## Global constraints

- Factorio 2.1, with and without Space Age.
- Quick loop: `busted spec/<file>_spec.lua`. Before each commit:
  `make fast` (the git hook runs it too). `make ingame` runs the in-game
  tests in both modes. `make check` runs everything.
- Every commit leaves `make fast` green. A task that changes the data
  stage also runs `make ingame`.
- `core/` reads no game globals. Mod paths start with
  `__abominable-ordnance__/`.
- Look up each API name with `make api NAME=<name>` before you use it.
- Load the functional-core skill before the first code change. Work
  test-first. Run `make format` before you stage Lua.
- Commit by the CLAUDE.md flow. Check that `git branch --show-current` is
  `art/v1-graphics` before each commit.
- No change to recipes, costs or balance numbers.
- A 256 px technology icon is `Common.icon(path, nil, 256)`.

## Review focus

1. A warded loaded larva shows the payload badge at (8, 8) and the ward
   badge at (-8, -8). Task 5 tests both on one item.
2. Without Space Age the cryo ward does not build. The unused-file test
   in Task 8 builds the cryo kind on purpose.
3. Another mod removes `big-remnants` or a vanilla machine. Tasks 3 and 4
   test that a nil sound and a nil corpse pass through without an error.
4. No building sheet, rocket base layer or badge has a `tint`. Tasks 2, 4
   and 6 assert it.
5. A 4×4 machine has an even size. Task 1 tests the boxes for 3, 4 and 5
   tiles, and Task 7 checks `tile_width` in the game.

### Task 2: The graphics module

**Files:**

- Create: `core/prototypes/graphics.lua`

**Interfaces:**

- Consumes: `Common.icon` from Task 1, `Names.CHAMBER`.
- Produces:
   - `Graphics.icon_path(file)` returns
     `"__abominable-ordnance__/graphics/icons/" .. file`.
   - `Graphics.tech_path(file)` returns the same under `technology/`.
   - `Graphics.machine(name, size)` returns a bare `graphics_set`, for
     `name` in `"breeding-pod"`, `"incubator"` and `"loading-chamber"`.
     An unknown name raises an error.
   - `Graphics.launcher(size)` returns a RotatedSprite.

     `simulation-chamber-working.ogg` and its `idle_sound` is
     `simulation-chamber-idle.ogg`, both under
     `__abominable-ordnance__/sound/loading-chamber/`, both at volume 0.7.
   - `Graphics.remnants(size)` returns the corpse prototype
     `"ao-loading-chamber-remnants"`.
   - `Graphics.loaded_larva(species, payload)` returns five icon layers.

- [ ] **Step 1: Write the failing tests** in `graphics_spec.lua`. Use these
  layer positions everywhere:
   - Pod and incubator: `animation.layers[1]` is the sheet, `[2]` is the
     shadow, and `working_visualisations[1]` is the emission.
   - Chamber: `animation.layers[1]` is the base and `[2]` is the shadow.
     The `working_visualisations` are `[1]` screen, `[2]` layer 4 and
     `[3]` glow.

     shift ≈ `{0, -0.5 * 5 / 7}`. The sheet has `frame_count = 60`,

     `draw_as_shadow = true` and `repeat_count = 60`. The emission
     visualisation has `fadeout = true`. Its animation has
     `draw_as_glow = true` and `blend_mode = "additive"`.
   - "keeps the incubator at its drawn size": scale 0.5. The sheet shift
     is `{2.5 / 64, 2.5 / 64}`, the shadow shift is `{51 / 64, 31 / 64}`,
     and the emission shift is `{0, 0}` with `line_length = 9`.
   - "fits the chamber to 4×4": scale ≈ `0.5 * 4 / 6`. The screen has 255

     `{-2 * 4 / 6, -1.75 * 4 / 6}`. Layer 4 has the layer4 filename and
     no glow flag. The glow has `draw_as_glow` and
     `blend_mode = "additive"`. The shadow has `draw_as_shadow`. No
     visualisation has `apply_recipe_tint`.
   - "has no tint on any building sheet": walk all three sets.
   - "fits the launcher to 3×3": `direction_count = 64`,
     `line_length = 8`, width and height 512, scale 0.225. `layers[2]`
     has `draw_as_shadow` and shift `{1.5, 0}`.
   - "builds the chamber remnants": `type = "corpse"`, the name, tile
     size 4, selection box ±2.0, and an animation with the remnants
     filename, `direction_count = 1` and scale ≈ 0.333.
   - "tints only the band and larva layers": for the biter and the
     explosive payload, layer 1 is `larva-rocket-base.png` with no tint.
     Layers 2 to 4 are the rear band, the front band and the larva, each

     shift `{8, 8}` and no tint.
   - "names files in two folders": `icon_path("stasis-ward.png")` and
     `tech_path("stasis-ward.png")` differ.
   - "rejects an unknown machine".
- [ ] **Step 2:** Run the spec. Expect it to fail on the missing module.
