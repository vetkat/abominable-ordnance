# Slice 2 (ordnance) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps
> use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn eggs into ammunition. Larvae take one of three payloads.
A loaded larva becomes a monster on a tamed force, and its payload goes
off when it dies.

**Architecture:** Pure core modules build the prototypes
(`core/prototypes/ordnance.lua`) and make the runtime decisions
(`core/payloads.lua`, `core/species.lua`). `data.lua` and `control.lua`
stay thin shells. Loaded monsters are vanilla units. `storage.loaded`
holds each one's payloads by unit number.

**Tech Stack:** Factorio 2.1.24 Lua, busted for the core, factorio-test
for the in-game tests, `make check` for all gates.

**Spec:** `docs/superpowers/specs/2026-11-14-ordnance-design.md`
(approved 2026-11-14, with the answers to Q1 to Q8).

## Global Constraints

- The target is Factorio 2.1, with and without Space Age.
- Every number lives in `core/balance.lua`.
- A core module never names `game`, `storage`, `script`, `defines`,
  `data` or `prototypes`. `spec/architecture_spec.lua` enforces this.
- The control stage uses no `math.random`.
- Every new item, recipe, technology and machine gets a name in
  `locale/en/locale.cfg`. `spec/locale_spec.lua` enforces this.
- A change to mod code gets a line under Unreleased in `CHANGELOG.md`.
- Commits: `make format`, `git add`, `make stamp`, `git commit`, each as
  its own command. Each PR uses `gh pr merge --auto --squash` (the
  maintainer asked for auto-merge on 2026-11-14).
- Look up each Factorio API name in `.factorio-api/factorio/library/`.

## Probe results (2026-11-14, both modes)

A throwaway in-game probe answered the spec's five questions:

1. A spoil trigger fires in a character's inventory, in a chest and on a
   belt. `source_position` and `target_position` are the position of the
   entity that holds the item. One egg alone fires one trigger.
2. A big biter on `ao-tamed` with an `attack_area` command killed a
   spawner 12 tiles away within 15 seconds.
3. An `explosive-rocket` created with its target at its own position
   explodes at once. It killed wooden chests of both forces and hurt a
   player character, despite the cease-fire.
4. A `poison-cloud` on `ao-tamed` hurts characters and units of every
   force, but not chests. An `acid-splash-fire-spitter-big` on `ao-tamed`
   hurts only `enemy` units that stand in it. A player character in it
   took no damage.
5. `on_entity_died` runs before `on_object_destroyed`, in the same tick.

So the acid death effect needs more than one puddle to matter. This plan
places five: one at the death spot and four around it.

## Review Focus

1. A save made with slice 1 loads slice 2: `on_configuration_changed`
   must create `ao-tamed` and `storage.loaded`. Test: Task 7 calls the
   setup function twice and checks the force.
2. A loaded monster that leaves the game without dying (a mod destroys
   it): its `storage` entry must go away. Test: Task 8 destroys a loaded
   monster with `destroy()` and checks `storage.loaded`.
3. Another mod removes a payload effect prototype: the death handler
   must skip it, not crash. Test: Task 5 unit test on
   `Payloads.on_death` with an `exists` stub.
4. A native unit dies: the death handler must ignore units with no
   `storage` entry. Test: Task 8 kills a plain native biter and checks
   that no error occurs and no effect appears.
5. A nest killed by `ao-tamed` drops eggs even though `ao-tamed` has no
   research (Q8). Test: Task 8.
